# API v1 (used by the Flutter app)

Base: `https://astrorajnathjha.com/api/v1` · JSON · rate-limited (120/min per user or IP; OTP endpoints are stricter).
Errors: validation → `422 {"message", "errors": {field: [..]}}`; others → `{"error": {"code", "message"}}`.

## Auth (email or mobile OTP)
| Method | Path | Body | Result |
|---|---|---|---|
| POST | `/auth/otp/start` | `identifier` (email, 10-digit Indian mobile, or +country number) | `201 {challenge, channel, sent_to (masked), is_new_account, expires_in, resend_in}` |
| POST | `/auth/otp/resend` | `challenge` | `200 {resend_in}` · `429 too_soon / rate_limited` |
| POST | `/auth/otp/verify` | `challenge, code, device_name, platform (android/ios/web)`, new accounts: `name, accept_terms=true` | `200/201 {token, token_type:"Bearer", expires_at (90 days), created, user}` · `422 invalid / expired / locked` |
| POST | `/auth/logout` | — (Bearer) | `204` |

## Account (Bearer token, `customer` ability)
| Method | Path | Notes |
|---|---|---|
| GET / PATCH | `/me` | PATCH: `name`, `locale` (en, hi), `notification_prefs` {booking_reminders, reports_ready, payments, offers} |
| GET | `/me/devices` | signed-in app devices, `current` flag |
| DELETE | `/me/devices/{id}` | sign out a device (own devices only) |
| GET / POST | `/birth-profiles` | POST: `label, name, gender?, birth_date (Y-m-d), time_accuracy (exact/approximate/unknown), birth_time (H:i, unless unknown), place_id, dst_choice? (earlier/later), is_primary?` |
| GET / PUT / DELETE | `/birth-profiles/{ref}` | someone else's ref → 404 |

A birth profile response includes `birth_utc` (ISO 8601 Z), `utc_offset_seconds` and `tz_resolution`
(`exact`, `ambiguous_earlier`, `ambiguous_later`, `gap_shifted`). When the time was ambiguous or did
not exist because of a clock change, the response also has a `notice` text.

## Public
| GET | Path |
|---|---|
| | `/meta`, `/catalogue/families`, `/catalogue/offerings?family=&q=`, `/catalogue/offerings/{slug}`, `/places?q=` (GeoNames, CC BY 4.0) |

Money is always given in integer paise (`price_minor`); `null` means "price on request".

## Wallet and payments (Bearer token, `customer` ability)
| Method | Path | Notes |
|---|---|---|
| GET | `/wallet` | `{cash_minor, bonus_minor, available_minor, reserved_minor, held_minor, payments_available, payments_mode (test/live)}` |
| GET | `/wallet/packages` | active recharge options `{ref, name, amount_minor, bonus_minor}` |
| GET | `/wallet/transactions?before={id}` | statement, newest first, 30 per page, `next_before` cursor |
| POST | `/wallet/recharges` | header `Idempotency-Key` (8–64 chars, required); body `package_ref`. `201 {ref, status, …, checkout}`. `checkout` holds the Razorpay Android SDK options (`key`, `order_id`, `amount`, `currency`, `prefill`); it never contains secrets. Same key → same payment. `503 payments_unavailable` when online payment is off |
| POST | `/payments/{ref}/confirm` | body = the three values the Razorpay SDK returns: `razorpay_payment_id, razorpay_order_id, razorpay_signature`. The server verifies the signature and re-fetches the payment from Razorpay before crediting. `422 signature_invalid` |
| POST | `/payments/{ref}/refresh` | re-checks status with Razorpay (6/min) |
| GET | `/payments`, `/payments/{ref}` | `status`: created, pending, captured, failed, cancelled, ambiguous |

A `failed` payment can still become `captured` if Razorpay reports a late success; the app should
show the server's status, not its own guess. Bonus credit is spent first and is not refundable.

## Webhooks
`POST /api/webhooks/razorpay` — Razorpay only. HMAC-SHA256 of the raw body with the webhook secret
(`X-Razorpay-Signature`); replays deduplicated by `X-Razorpay-Event-Id`.
